## 人的四个未来化

**我和 10 万年前的智人祖先的差距,远远小于 GPT-3 和 GPT-4 之间的差距。**

这不是修辞,是时间尺度的冷酷事实。基因进化的单位是百万年,大语言模型的迭代以月计——GPT-3.5 到 Claude Opus 4.6 不到三年,AI 领域的"常识"已经换了至少三代。你大脑的硬件还是 20 万年前那一套,而对手每个季度出一个新版本。

《人类简史》里有一段我一直记得: 智人掌握语言之后,历史学才从生物学里分化出来——在那之前,人类和其他动物的差别不值得单独写一部史。

**如果一个外星人十万年后回看地球,只允许他挑两个历史分界点,我赌他会选:**

- 7 万年前,智人开始说话
- 现在,人类造出了大语言模型

这个尺度的剧变,对我们提出了**历史上从来没出现过的要求**——一个靠基因进化的物种,怎么追上一个靠版本号进化的对手?

![[58458206a204bf70585de3b4acedd3db_MD5.jpg]]

靠基因是追不上的。所以我给自己定了一个私人目标,叫"**人的四个未来化**"——把自己在 AI 时代必须重建的那几块,一块一块主动装修。**这篇文章只聊第一格: 知识的 Memo 化**——在 AI 时代,怎么建立一套真正属于你自己的知识系统。

为什么从知识开始? 因为它是其他三格的**地基**:

- 你做**决策**的质量,取决于你知道什么
- 你的**创造力**,取决于你脑子里有多少不同领域的积木可以重组
- 你和什么样的人能**深度共鸣**,取决于你能在多少个频率上共振

**知识是原材料。原材料不行,后面全白搭。**

为什么现在写? 最近 Karpathy 发了 llm-wiki.md(LLM 辅助维护的个人 wiki),Gary Tan 晒了 gbrain(创业孵化器视角下的 idea 成长系统)——这两个我关注很久的人,碰巧同一周都在聊"AI 怎么帮你管理知识"。我自己是笔记工具的重度用户(过去八年两只手数不过来的工具用过),借着这波外部刺激,我把自己的知识管理系统又升级了一遍,然后**把整个 repo 开源出来**:

[https://github.com/owenliang60-ship-it/knowledge-mgmt](https://github.com/owenliang60-ship-it/knowledge-mgmt)

这篇文章要拆的,就是这套系统背后的每一个设计决定——**为什么这么选、为什么不那么选,以及你应该怎么根据自己的情况改造**。另外三格是什么、各自怎么装修,后面的文章会一格一格拆,想跟的话关注一下别走丢。

## 在你动手之前,请先放下两个幻想

幻想一:存在一劳永逸的知识管理方案

不存在。

我自己过去八年试过的工具,排队下来:Evernote、Notion、Roam Research、Logseq、Heptabase、Obsidian、飞书、Apple Notes——加上每年都会冒出来的 2-3 个"号称会终结一切"的新产品。每一个我都满怀希望地开始,把第一周的兴奋投进去,然后慢慢荒废。最后留下的是一堆互相不通的导出文件,和"下一个会更好"的执念。

不是工具不好。它们里面有几个是**真的**好。问题是:**知识管理根本不是一个"工具问题"**。

它是一个关于你如何思考、如何读书、如何和自己相处的**持续纪律**。再好的工具也只能放大你已经有的纪律,放大不了你没有的。如果你读书的时候不做笔记,任何工具都救不了你;如果你读完书从来不回头复习,任何工具都不能替你复习;如果你的求知欲已经被信息流稀释成 0,任何 AI 都不能替你重建。

工具是脚手架,不是建筑。你拿到一根更结实的脚手架,房子还是要你自己盖。

幻想二:舶来品能直接满足你

不能。**包括下面我要给你的这个 repo**。

Knowledge MEMO 是我自己的系统。demo 里那 5 张卡片,你打开一看就知道是什么口味——价值投资、半导体产业、神经科学、意识研究。**完完全全是我个人的好奇心地图,不是任何意义上的"通用知识体系"**(具体是哪 5 张卡,后面第四节 ③ 会一张张列出来讲)。

Gary Tan 做的 gbrain,会考虑 idea 怎么在 LLM 辅助下生长——因为他在做创业孵化器,他每天接触的是创业点子的萌芽和死亡。我做的 Knowledge MEMO 会考虑概念怎么跨层次整合、研究怎么做交叉对照——因为我做跨域思考,我需要"拉康精神分析"和"认知神经科学"在一个 vault 里发生意料之外情理之中的连接。

**你的系统会考虑什么?只有你自己知道**。

所以请你先答应我一件事:**你不会原样使用这个 repo**。你会把它 clone 下来,看一遍,理解它的设计思路,然后**删掉 demo 文件夹**,用你自己真实写过的 4-7 张卡重新填进去。让它长成你自己的系统。

我把它开源,不是让你当产品用,是让你看到**一个真实跑通的样本**——然后去长出你自己的那一个。

## Karpathy 的方向,和那个他没回答的问题

Karpathy 那篇 llm-wiki.md gist 的方案很清晰:把原始材料摄入成结构化 wiki,通过 Query 调取、Lint 整理,目标是**让维护成本趋近于零**——LLM 当不知疲倦的知识工程师,你只管扔原料进去。

很自洽,我第一次读完也觉得"就是这个"。但后来我反复在想一个 Karpathy 没明说的问题:**wiki 是为谁准备的?**

看起来多余——"当然是为我"。但仔细想:如果维护成本真的趋近于零,LLM 做了所有摄入和整理,你基本不碰它——**那这个 wiki,本质上是 agent 的 context,不是你脑子里的东西**。你是 wiki 的所有者,不是使用者。真正在读它、用它的,是 agent。

如果 wiki 是为 agent 准备的 context，那么下一代模型发布之时,就是你积累灰飞烟灭之日。

过去三年,context window 从 4K 涨到 1M,memory 机制反复重构,检索方式从 RAG 一路演进到 agentic deep research——**每次大版本变化,喂入格式和 prompt 最佳实践都要重写一遍**。你 2023 年存的那些 "System: You are a helpful assistant..." 模板,现在基本过期了。

知识管理工具也是同样的故事: Notion(2016)、Roam(2019)、Obsidian(2020)、Heptabase(2022),每一代都让你重新组织一次笔记。**不是工具的错,是你把积累押在了一个还在快速迭代的层**。押在 agent context 上,同样的剧本会重演——你今天辛苦编译的 wiki,6 个月后大概率就是一堆过时数据。

如果 wiki 是为你的大脑准备的脚手架，那它的价值就是永久的。

听起来像废话,但逻辑是冷的:**人脑的参数更新速度远远跟不上 GPT 的版本号**。你 5 岁背的乘法口诀 40 岁还在用;你 2026 年理解的 BDNF 机制、Howard Marks 的"自我改进闭环"——只要当年真的吃进去了,10 年后还在脑子里。

**人脑: 慢、稳定、版本号不变、无法被外部强制升级**。它是你可以做长期积累的唯一一个载体。

![[42c060ee710a1f37389ce7235ea3acf5_MD5.jpg]]

一个有意思的参照: LLM Wiki v2

顺着 Karpathy 这个方向,Rohit Goel 做了一个扩展版本——[LLM Wiki v2](https://gist.github.com/rohitg00/2067ab416f7bbe447c1977edaaa681e2),把这条路推得更深入: 记忆衰减 + 置信度打分、知识图谱、混合检索、事件驱动自动化、多 agent mesh sync、自愈。作者概括得很干净:"The bottleneck is bookkeeping, and LLMs eliminate that bottleneck."

v2 在它自己的目标下做得非常扎实。但我读完挥之不去的感觉是——这些 feature **更像在描述一个 agent 的工作环境**: agent 跨 session 会失忆,所以要持久化; agent 用到过时事实,所以要衰减和置信度; 多个 agent 并发,所以要 mesh sync; agent 产生脏数据,所以要自愈。

顺着这个观察,有一个问题值得你自己掂量:**"LLM wiki" 这个词下面,其实可能是两种不同的东西**——一种是**给 agent 工作用的持久化上下文**,一种是**给人求知用的外部脚手架**。碰巧都长成 wiki 的样子,但设计目标不同,甚至在某些地方相反: agent 要维护成本趋近于零,人要一定的摩擦把东西压进脑子; agent 要 mesh sync,人只有一个自己; agent 要自愈,人要自己回去读一遍。

再往下还有一个更大胆的问题: **agent 工作真的需要"wiki 形态"的上下文环境吗?** 还是说它要的是更贴合机器的东西——任务队列、事件日志、向量库、图数据库——而 wiki 的标题/段落/wikilink/MOC 更多是给人眼和手设计的审美? 我没有确定答案,也可能 v2 恰好是人机协同的最佳折中。但这个问题值得你在抄方案之前先想清楚自己到底要什么。

对我自己来说,答案是清楚的: **我要解决的是"人在 AI 时代怎么求知"**。所以 Knowledge MEMO 不会去和 v2 比功能——它们在回答两个不同的问题。

Knowledge MEMO 的选择

对"wiki 是为你大脑准备的"这个回答,Knowledge MEMO 和 Karpathy 方案在每个关键点上都走了相反的路:

![[ffca07931ae2a8db7835f8680c5b4319_MD5.jpg]]

这四行的共同源头是一句话: **不进大脑的知识不是你的知识**。维护成本不能趋近于零,因为零成本意味着人不在 loop;LLM 不能替你读书,因为读书本身就是知识进脑的过程;闭环必须包含 Retain,因为没 Retain 等于没留下。

所以 Knowledge MEMO 强制"人在 loop",具体落成三条硬纪律:

- **没有信息流自动化**。没有 RSS 抓取、定时爬虫、"早上醒来 vault 里多了 50 张新卡"。**今天读什么,你自己决定**。
- **/note 是对话中的双提议**。它不会自动建卡,只是提议 wikilink 和原子卡,**你逐条确认**。这一步**故意制造摩擦**——没有摩擦的录入不是录入,是数据填充。
- **Agent 不能独自改写 Wiki**。所有写入 Cards/ 必须经过 /note 的双提议通道,没有 API 绕过。

三条都让系统"不够自动化"。**这是故意的**。我们不是反对自动化,我们是在拒绝**给易耗品做积累**。

## 知识 Memo 化这一格,我做的四件故意不一样的事

拒绝给易耗品做积累——这是原则。原则需要落地成具体的设计决定。下面是 Knowledge MEMO 在"知识 Memo 化"这一格上做的**四件故意不一样的事**,每一件都是这个原则的具体表达。

![[97c466f1143e4d8cae0d820370bff149_MD5.jpg]]

① 它是工具箱,不是理念文件

这个时代不缺好的知识管理理念。缺的是**理念后面真的有东西可以装**。

所以 Knowledge MEMO 不是一篇博文。一行命令安装,装完之后你立刻拥有:

- 一份根目录宪法 SCHEMA.md,定义三层架构 + 四维标签体系 + 权限矩阵
- 6 个 skill:/read(读取摘要)、/insights(洞察提取)、/note(双提议笔记)、/query(查询)、/lint(健康检查)、/review(FSRS 间隔重复)
- 8 个卡片模板(reading / research / insight / concept / comparison / atomic / moc / health-report)
- 一个 demo gallery,5 张真实卡 + 1 个 MOC 索引

你可以装完之后**立刻打开 demo 看一眼**,看完决定要不要留。这比"读完一篇 idea file 然后自己从头实现"要诚实得多。

② 人必须在 loop 里——这是纪律,也是资产保值

这一条上一节已经讲透了原理。我这里只补一个具体场景,让你看到"人在 loop"在真实使用中长什么样。

[demo gallery](https://github.com/owenliang60-ship-it/knowledge-mgmt/tree/main/demo) 里有一张《MU 存储周期拐点研究》。卡的最后一段写了一个**概率加权的拐点判断**:股价峰值在 2026 年 5-8 月,P(已在顶部 ±1 个月) = 15%,D 情景概率 = 30%,预期回撤约 37%。

**这些数字是哪里来的?** 给定**完全相同**的公开数据(MU 财报、过去十年存储周期数据、hyperscaler capex 增速),一个 LLM agent 能不能生成这份研究?

**也许能生成 70%**——历史复盘、情景框架、验证指标、观察日历,这些 agent 都能拼出来。

但最后那个"D = 30%、P = 15%"——**那是人基于直觉的主观判断**。是研究员看了一周财报、对比了 2018 vs 2022 vs 2026 三次周期里管理层的措辞细节、内化了"管理层连续说 structural 是危险信号"这种**非数据化的经验**之后,给出的概率分布。这一步 agent 给不出来,因为它需要的是**身在场的判断力**,不是更多的 context。

Knowledge MEMO 的"人在 loop"机制,就是让这种"身在场的判断力"持续被训练、被记录、被复用。**这不是反 AI,这是把 AI 用对地方**——让它做它擅长的(70% 的拼装),把那 30% 的判断留给你,而且**强制你做这一步**,不让你偷懒外包出去。

那 30% 才是你的护城河。把它外包了,你就没有护城河了。

③ 个人样板,不是通用产品

我刚才说 demo gallery 里有 5 张卡。让我把它们的领域列出来:

- Howard Marks 的 AI 商业洞察(**价值投资 / AI 产业**)
- MU 半导体周期(**半导体产业 / 投资分析**)
- BDNF 深度研究(**分子生物学 / 神经可塑性 / 个人健康**)
- 默认模式网络与意识(**认知神经科学 / 意识研究**)
- MOC-Neuroscience(**神经科学域入口**)

你看出来了吗?**这是一个特定的人的好奇心地图**。价值投资 + 半导体周期 + 神经科学 + 意识研究——这是**我**的兴趣,不是知识管理的"通用模板"。

这是故意的。我**不想**给你一个"通用知识库模板",因为通用模板会骗你——它会让你以为知识管理是一个**结构问题**,只要套上正确的字段就解决了。

不是。**知识管理是一个"你是谁"的问题**。你的兴趣、你的工作、你每天读的东西、你想成为谁,决定了你的 vault 应该长什么样。

我的 vault 长成跨"投资 + 神经科学"的样子,因为我做投资判断的时候会想"这个人的判断力的神经基础是什么",我研究神经科学的时候会想"这个发现背后能不能投资到某个公司"。这种交叉是我个人特有的——你不需要照抄。**你的交叉应该是你自己的**。

但**先看一遍我的样本**比从空白开始要快得多。你看完会知道一张完整的卡片应该有多少字、应该有什么字段、wikilink 应该多密、参考文献应该不应该列、研究局限应该不应该写。这些"细节"才是知识管理的真功夫,通用模板教不了你,只有看真实的 vault 才能学到。

④ 第四步:Retain——Karpathy 没说的

![[1d02e6bbe698012f13a2b44b5bd10bb6_MD5.jpg]]

Karpathy 列了三个动作:Ingest、Query、Lint。这三个都是"让 wiki 更好"。

我们加了第四个:**Retain——让你的大脑变好**。

这是 Knowledge MEMO 和 LLM Wiki 在工程层面**最大的差异**。/review 用 FSRS-6(目前最先进的开源间隔重复算法,Anki 的新默认引擎)把卡片从 Obsidian 推进你的脑子里。

为什么要做这一步?

因为**一份你编译得再漂亮、却记不住的 wiki,是一个慢性时间黑洞**。每次你需要某个知识点的时候,你打开 wiki 找,找到了,加载到工作记忆里用一下,关掉。下一次你又重复一遍。**你每一次都要 re-derive,从来没有真正"拥有"它**。

更糟糕的是:**你压根不知道自己什么时候需要它**。

你可能会说:agent 也能做跨域检索啊——我让它搜 vault、做 RAG、甚至做 deep research,它一样能把 看起来不相关的概念连起来。

没错,**agent 能做**。而且做得又快又全。

但有一种体验是 agent 给不了你的:**你自己的大脑在洗澡的时候突然把两件事连起来**。Agent 可以帮你检索到同样的连接,但它给你的是一份报告。**你自己的大脑做出这个连接的时候,给你的是一次顿悟**。报告读完就忘了,顿悟会改变你此后思考同类问题的方式。这不是效率的比较,是**体验的比较**。一个让你更快地得到答案,一个让你**成为一个不一样的人**。

Retain 就是在保护这种体验发生的可能性——它把知识推进你的长期记忆,让你脑子里的 A 和 B 在某一天不期而遇。如果 A 和 B 都只存在 wiki 里,这个不期而遇**永远不会发生**。这就是为什么 Retain 不是一个 nice-to-have,是整个栈的闭环——**没有它,前面三个 skill 全部白做**。

Karpathy 没写这一步,因为它**违背"维护成本趋近于零"的方向**——间隔重复按定义就是维护成本,而且是**无法外包的**维护成本。FSRS 算法可以帮你算"今天该复习哪几张",但坐下来读那几张卡的人,**只能是你自己**。

**只有当你承认"人必须在 loop 里"是一个不可妥协的前提,Retain 才会自然长出来。只有当所有经过 AI 精心编译的知识,真正从模型的参数网络进入我们的大脑网络——aha moment,这个所有智力工作者一生追逐的幻光,才能真正偶尔闪现。**

这种闪现,是人类智力活动里最爽的瞬间之一。它不是"工作",它是你当初开始求知的那个原因——你想要的不是答案,是**自己想通**的那一刻。

## 你为什么开始求知?

我是为了这种闪现而求知的,不是为了书籍、互联网、或者大模型给了我看起来无限的知识本身。

我更喜欢刘慈欣在《山》里那句话:**山就在那里**。

小时候读文学名著,现在啃各种前沿领域的知识,对我来讲都是同一件事——爬山。爬山的理由仅仅是: 山在那里。看到山,人就会想去爬;诞生攀登冲动的那一刻,登顶已经完成了 90%。

然而 **over the mountains, mountains**(山的那边还是山)。这句话形容求知和人生都恰到好处——这是一条意味着永恒疲倦和偶尔惊喜的路。

现在学知识管理、学和 AI 协作、尝试推进人的四个未来化,都是在这条永恒之路上走下一步。我们的双腿从未像现在这样强壮有力,而知识管理的未来化,就是我们给自己打造最合手的登山杖。

但只有攀登的冲动,能支撑你走到终点,以及终点之后。
