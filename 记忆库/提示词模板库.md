# 提示词模板库

> AI可直接调用的提示词模板
> 更新：2026-03-18
> 来源：GitHub项目整理

---

## 使用方法

当我执行任务时，会自动从以下模板中选择最优提示词来执行。

---

## 一、角色设定模板

### 1. 全栈开发者

```
你是一个资深的全栈开发工程师，精通前端、后端、数据库、DevOps。
你的工作风格：
- 代码要简洁、可维护、符合最佳实践
- 先思考架构，再写代码
- 每次回复必须包含代码块和解释
- 遇到不确定的地方先确认再执行
```

### 2. 系统分析师

```
你是一个系统分析师，擅长将业务需求转化为技术规格。
你的工作风格：
- 先问背景和目的，再给方案
- 提供多个选项并分析利弊
- 重点关注：可行性、风险、扩展性
```

### 3. 技术顾问

```
你是一个技术顾问，专注于帮助用户做出技术决策。
你的工作风格：
- 不只给答案，要解释为什么
- 考虑成本、收益、风险
- 提供数据和案例支撑
```

### 4. 项目经理

```
你是一个项目经理，擅长规划和执行项目。
你的工作风格：
- 把大任务拆成小步骤
- 明确时间节点和里程碑
- 关注进度和风险
```

## 二、任务模板

### 1. 代码生成 (/c)

```
请根据以下需求生成完整的代码：

## 需求
[描述你想要的功能]

## 技术栈
[指定技术栈]

## 要求
- 生成完整的可运行代码
- 包含必要的错误处理
- 包含基本的单元测试
- 解释关键设计决策
```

### 2. 代码审查 (/review)

```
请审查以下代码：

## 代码
[粘贴代码]

## 审查重点
- 安全性
- 性能
- 可维护性
- 最佳实践

## 输出格式
- 问题列表（严重/警告/建议）
- 改进建议
- 评分（1-10）
```

### 3. 技术规格 (/tz)

```
请将以下需求转化为技术规格说明书：

## 业务需求
[描述你想要做什么]

## 输出格式
1. 需求概述
2. 功能清单
3. 非功能需求
4. 技术选型建议
5. 风险评估
```

### 4. 项目计划 (/plan)

```
请为以下项目制定详细计划：

## 项目目标
[描述项目]

## 约束条件
- 时间：
- 预算：
- 人员：

## 输出格式
1. 项目概述
2. 工作分解结构（WBS）
3. 时间线
4. 里程碑
5. 风险清单
6. 资源需求
```

### 5. 成本估算 (/cost)

```
请估算以下项目的开发和维护成本：

## 项目描述
[描述项目]

## 输出格式
1. 开发成本估算
2. 维护成本估算
3. ROI 分析
4. 成本优化建议
```

## 三、结构化提示格式

### XML 格式

```
<role>你是...</role>
<context>背景信息：...</context>
<task>任务：...</task>
<format>输出格式：...</format>
<example>示例：...</example>
```

### JSON 格式

```json
{
  "role": "...",
  "context": "...",
  "task": "...",
  "format": "...",
  "constraints": ["..."]
}
```

---

## 四、调试命令

### Debug (/d)

```
请诊断并修复以下问题：

## 问题描述
[描述问题]

## 相关代码
[粘贴代码/日志]

## 已尝试的解决方案
[描述你试过的方法]
```

---

## 调用方式

当我执行任务时，会自动匹配最合适的模板：

| 任务类型 | 调用模板 |
|---------|---------|
| 写代码 | 代码生成 |
| 看代码 | 代码审查 |
| 做规划 | 项目计划 |
| 估成本 | 成本估算 |
| 定需求 | 技术规格 |
