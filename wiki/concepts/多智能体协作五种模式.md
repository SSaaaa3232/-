# 多智能体协作五种模式

> 从最简单的、能跑通的模式开始，观察它在哪里会遇到瓶颈，然后再逐步升级。
> — Anthropic 官方

## 选择原则

**从「调度-子智能体」开始**，它能以极低协调成本解决最广泛的问题。先跑通，再根据瓶颈升级。

## 五种模式速查

| 模式 | 适用场景 | 核心机制 |
|------|---------|---------|
| **生成-验证者** | 看重质量，有明确评估标准 | 生成→验证→反馈循环 |
| **调度-子智能体** | 任务拆解清晰，子任务短平快 | 层级制，主导者派发+汇总 |
| **智能体团队** | 并行长任务，子任务相互独立 | 成员持久化，积累领域知识 |
| **消息总线** | 事件驱动，系统持续扩展 | 发布/订阅，路由器分发 |
| **共享状态** | 协作研究，需频繁共享发现 | 共享"黑板"，去中心化 |

## 各模式详解

### 生成-验证者（Generator-Verifier）
- 生成者输出初稿 → 验证者按标准评估 → 反馈修改 → 循环
- **关键**：验证标准必须明确具体，否则变成橡皮图章
- **陷阱**：死循环——生成者无法解决验证者的问题。需设最大循环次数+后备方案

### 调度-子智能体（Orchestrator-Subagent）
- 调度者规划+分配，子智能体执行，结果汇总
- **优势**：调度者保持对大目标掌控，子智能体聚焦细分
- **瓶颈**：调度者是信息瓶颈；未做并行处理时，多智能体成本但无速度优势

### 智能体团队（Agent Teams）
- 协调者分发，成员长期存在、积累上下文
- **优势**：成员越干越熟，适合多步骤长任务
- **陷阱**：独立性要求高——成员间难共享中间进度，竞争公共资源易冲突

### 消息总线（Message Bus）
- 发布/订阅机制，路由器精准派发
- **优势**：系统扩展方便，新成员订阅即可上岗
- **陷阱**：调试困难（多米诺式触发难溯源）；路由错误导致静默崩溃

### 共享状态（Shared State）
- 所有智能体共读写一个持久存储（数据库/文件/文档）
- **优势**：消除单点故障；发现可实时流转
- **陷阱**：反应式死循环——智能体互相回复无限循环。**必须设置终止条件**

## 选择决策树

```
子任务需要长期保留记忆？
  否 → 调度-子智能体
  是 → 智能体团队

工作流是否事件驱动？
  是 → 消息总线
  否 → 已知步骤 → 调度-子智能体

智能体间需要频繁共享发现？
  是 → 共享状态
  否 → 智能体团队

需要质量审核闭环？
  是 → 生成-验证者
```

## 组合使用

模式不互斥。常见组合：
- 整体用**调度-子智能体**，某个子任务内部用**共享状态**
- **消息总线**分发事件 + 每类事件末端挂**智能体团队**
