# 润色

## 原始线索

- GitHub 项目参考：`humanizer`
- Skill 参考：达尔文 skill 背后的评分原理
- 平台参考：OpenReview
- 研究参考：Automated Essay Scoring, AES
- 机器学习参考：ensemble voting

## 核心想法

做一个面向论文润色的 skill，不是简单把文本改得更“高级”，而是建立一个多维度、可评分、可仲裁的润色流程。

核心原则：

- 先保真，再润色。
- 不新增原文没有的论点、数据、机制、引用或结论。
- 优先保证术语一致性和学术准确性。
- 让表达更清晰、自然、正式，但避免过度美化。
- 对高风险改动进行标注或解释。

## 可以借鉴的几个来源

### 1. humanizer

`humanizer` 可以作为表达自然化的参考方向。

可借鉴点：

- 让文本更像人类自然写作，而不是模板化机器文本。
- 降低过度机械、过度正式、过度堆砌的表达。
- 优化句子节奏和段落可读性。

需要注意：

- 论文润色不能只追求“像人写的”。
- 学术文本首先要准确、严谨、可追溯。
- 不能为了自然化而牺牲术语、逻辑和原意。

### 2. 达尔文 skill 的评分原理

达尔文 skill 背后的评分思路可以抽象成：先建立评价维度，再根据评价结果迭代优化。

可借鉴点：

- 不只产出结果，还要评价结果。
- 用评分维度约束输出质量。
- 通过多轮检查发现薄弱项。
- 让修改过程从“凭感觉润色”变成“按标准优化”。

在论文润色里，可以把评分维度设计为：

- Faithfulness：是否忠实原意
- Grammar：语法是否正确
- Academic tone：是否符合学术语体
- Clarity：表达是否清晰
- Coherence：逻辑是否连贯
- Conciseness：是否简洁
- Terminology：术语是否稳定

### 3. OpenReview

OpenReview 可以作为“学术评审视角”的平台参考。

可借鉴点：

- 评审不是只看语言，还看论证、贡献、清晰度和可信度。
- 反馈应该有结构，而不是泛泛地说“写得更好”。
- 可以把 reviewer 的思路引入润色流程。

例如润色 skill 可以模拟几类审稿视角：

- Language reviewer：检查语言和语法。
- Academic style reviewer：检查学术表达和正式程度。
- Logic reviewer：检查句间关系、论证链条和段落结构。
- Faithfulness reviewer：检查是否改变原意。
- Terminology reviewer：检查术语、缩写、领域词是否一致。

### 4. Automated Essay Scoring

Automated Essay Scoring 研究的是如何让机器自动评价作文或文本质量。

对论文润色 skill 的启发：

- 需要明确 rubric，而不是只靠模型主观判断。
- 可以把文本质量拆成多个维度评分。
- 可以在润色前后比较分数变化。
- 可以让模型输出分数、理由和修改建议。

可以参考 AES 的评价维度：

- 内容完整性
- 组织结构
- 语言质量
- 连贯性
- 任务相关性
- 论证充分性
- 可读性

迁移到论文润色中，重点不是给作文打分，而是判断：

- 润色后是否更清楚。
- 润色后是否更学术。
- 润色后是否更简洁。
- 润色后是否仍然忠实原意。

### 5. Ensemble voting

Ensemble voting 的核心思想是：不要只相信单一判断，而是让多个模型、多个规则或多个视角共同决策。

在论文润色 skill 中，可以设计成多评委流程：

- 语法评委：只看语法、拼写、标点。
- 学术表达评委：只看 formal tone、学术自然度。
- 逻辑评委：只看句间关系和论证流。
- 保真评委：只看有没有改动原意。
- 术语评委：只看术语、缩写、专业词是否一致。

最终由仲裁器综合这些意见。

仲裁优先级：

1. 不改变原意。
2. 不引入原文没有的信息。
3. 保持术语准确和一致。
4. 修复语法错误。
5. 提升清晰度和连贯性。
6. 提升学术风格。
7. 在不损失信息的前提下压缩冗余。

## Skill 的推荐流程

### 输入

用户提供：

- 原文段落
- 目标语言，例如英文或中文
- 领域，例如生物、计算机、教育、社会科学
- 目标期刊或写作风格，如果有
- 是否需要解释修改

### 第 1 步：识别文本类型

先判断文本属于哪种论文部分：

- Title
- Abstract
- Introduction
- Methods
- Results
- Discussion
- Conclusion
- Cover letter
- Reviewer response

不同部分采用不同润色策略。

例如：

- Abstract 要重视压缩和信息密度。
- Introduction 要重视逻辑铺垫。
- Methods 要重视准确和可复现。
- Results 要避免过度解释。
- Discussion 要重视论证边界和谨慎语气。

### 第 2 步：基础润色

输出一个初版润色结果，处理：

- 语法错误
- 拼写错误
- 标点问题
- 不自然表达
- 句子过长
- 重复和冗余

### 第 3 步：多维度评分

对润色结果进行评分：

| 维度 | 含义 | 目标 |
|---|---|---|
| Faithfulness | 是否忠实原意 | 必须最高优先级 |
| Grammar | 语法是否正确 | 尽量无错误 |
| Academic tone | 是否符合学术语体 | 正式但不浮夸 |
| Clarity | 是否清晰 | 读者容易理解 |
| Coherence | 是否连贯 | 句间关系明确 |
| Conciseness | 是否简洁 | 去除无效冗余 |
| Terminology | 术语是否一致 | 不随意替换专业词 |

### 第 4 步：风险检查

重点检查：

- 是否新增了原文没有的主张。
- 是否删掉了重要限定条件。
- 是否改变了因果关系。
- 是否改变了研究对象、实验条件或结论强度。
- 是否把谨慎表达改成了绝对表达。
- 是否误改专业术语。

如果发现问题，应回滚相关修改。

### 第 5 步：仲裁与最终输出

根据多个评委意见进行综合。

推荐输出结构：

```text
Polished version:
...

Key changes:
- ...

Risk notes:
- ...
```

如果用户只想要最终文本，可以提供简洁模式：

```text
...
```

## Skill 的一句话定位

一个基于 AES rubric、ensemble voting 和学术评审视角的论文润色 skill：用多评委评分和保真优先仲裁，把论文文本改得更清楚、更自然、更学术，同时避免改动原意。

## 后续可以扩展

- 做成不同模式：轻度润色、深度润色、审稿人视角、投稿前检查、回复审稿人润色。
- 加入术语表：用户可提供固定译法或领域术语。
- 加入差异对照：输出原句、修改句、修改理由。
- 加入评分报告：润色前后各维度评分对比。
- 加入 OpenReview 风格反馈：strengths、weaknesses、suggestions。
- 加入多版本输出：保守版、标准版、强化版。
